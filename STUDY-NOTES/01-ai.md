# `packages/ai` — `@earendil-works/pi-ai` Study Guide

A teaching-quality deep dive into the unified multi-provider LLM API. This is the
foundational package of the `pi` monorepo: it gives every consumer (the coding
agent, CLIs, etc.) **one normalized request/response/streaming shape** across
~15 providers and ~9 underlying chat APIs, plus image generation, model
catalogs, cost tracking, and OAuth.

All file references are absolute-relative to `packages/ai/`. Line numbers cite
the file at the time of writing.

---

## 1. Purpose & Public API Surface

### What the package does

- **Unify** many provider APIs (Anthropic Messages, OpenAI Chat Completions,
  OpenAI Responses, OpenAI Codex Responses, Azure Responses, Google Generative
  AI, Google Vertex, Amazon Bedrock Converse, Mistral) behind one set of
  functions and one message model.
- **Discover models** from a generated catalog (`models.generated.ts`, 16k+ lines)
  with full TypeScript autocompletion of provider + model id.
- **Track tokens & cost** in a normalized `Usage` shape.
- **Persist/serialize** conversations as plain JSON (`Context`), and **hand off**
  mid-conversation between providers (thinking blocks downgraded to text).
- Only includes **tool-calling-capable** models (essential for agentic use).

### Entry points (`package.json` subpaths)

- `.` → `src/index.ts` — main API (text/chat, models, images, registries).
- `./oauth` → `src/oauth.ts` → re-exports `src/utils/oauth/index.ts` (Node-only login flows).
- `./providers/*` → individual provider modules (`streamAnthropic`, etc.) for direct typed access.
- The `bin` runs `src/cli.ts` (`npx @earendil-works/pi-ai login`).

### `index.ts` exports (`src/index.ts:1`)

Re-exports TypeBox (`Type`, `Static`, `TSchema`) plus wildcard re-exports of:
`api-registry`, `env-api-keys`, `image-models`, `images`, `images-api-registry`,
`models`, `stream`, `session-resources`, `types`, and utils
(`diagnostics`, `event-stream`, `json-parse`, `overflow`, `typebox-helpers`,
`validation`). It re-exports the **faux provider** (`./providers/faux.ts`) and
the image **register-builtins**. Provider option types
(`AnthropicOptions`, `BedrockOptions`, `GoogleOptions`, `MistralOptions`,
`OpenAICompletionsOptions`, `OpenAIResponsesOptions`, `OpenAICodexResponsesOptions`,
`AzureOpenAIResponsesOptions`, `GoogleVertexOptions`) are `export type`-only.
A curated set of OAuth **types** is re-exported from `index.ts` (the OAuth login
**functions** live behind `/oauth`).

## 2. Architecture: the provider abstraction & request flow

### Two-level registry

There are **two distinct lookups**, do not confuse them:

1. **Model catalog** (`models.ts:4`) — keyed by `provider → modelId → Model`,
   loaded from `MODELS` in `models.generated.ts`. This is what `getModel`/`getModels`
   read. A `Model` carries an `api` field telling you *which API implements it*.
2. **API provider registry** (`api-registry.ts:40`) — keyed by `api → { stream, streamSimple }`.
   This maps an API name (e.g. `"anthropic-messages"`) to the actual streaming
   implementation.

`stream(model, context, options)` (`stream.ts:40`):
1. `resolveApiProvider(model.api)` looks up the API implementation
   (`stream.ts:32`) — throws if unregistered.
2. `withEnvApiKey(model, options)` (`stream.ts:22`) injects an env API key when
   the caller didn't pass one explicitly.
3. Delegates to `provider.stream(model, context, options)`.

`complete` is just `stream(...).result()`. `streamSimple`/`completeSimple` go
through the registered `streamSimple` functions instead.

### `api-registry.ts` — the registry

- `registerApiProvider(provider, sourceId?)` (`api-registry.ts:66`) stores wrapped
  stream functions. The wrappers (`wrapStream`, `api-registry.ts:42`) assert
  `model.api === api` and throw on mismatch — a guardrail that the catalog and
  the dispatch agree.
- `sourceId` enables scoped teardown via `unregisterApiProviders(sourceId)`
  (`api-registry.ts:88`) — used by the faux provider so tests can register/clean up.
- `clearApiProviders()` (`api-registry.ts:96`) wipes the registry (used by
  `resetApiProviders`).

### `register-builtins.ts` — lazy registration

`src/providers/register-builtins.ts` is imported for side effect at the top of
`stream.ts:1`, so calling `stream` always registers the 9 built-in APIs first
(`registerBuiltInApiProviders`, `register-builtins.ts:345`, called at module
bottom `:406`).

The crucial design point: **provider implementation modules are loaded lazily via
dynamic `import()`** (`register-builtins.ts:206-324`). Each builtin's `stream`
is a `createLazyStream` wrapper (`register-builtins.ts:162`) that returns an outer
`AssistantMessageEventStream` immediately, then dynamically imports the heavy
provider module (and its SDK) and forwards events. This keeps the cold-start and
browser bundle small — you only pay for `@anthropic-ai/sdk`, `openai`,
`@google/genai`, `@aws-sdk/...`, `@mistralai/...` when you actually call that
provider. Bedrock additionally uses `importNodeOnlyProvider` (`register-builtins.ts:89`)
which rewrites `.ts`→`.js` and is Node-only (browsers can list but not call Bedrock).
A test seam `setBedrockProviderModule` (`register-builtins.ts:125`) lets tests
inject a mock without AWS SDK. If a lazy import throws, the error becomes an
`AssistantMessage` with `stopReason:"error"` pushed onto the stream
(`createLazyLoadErrorMessage`, `register-builtins.ts:141`) — consistent with the
"errors are encoded in the stream, never thrown after invocation" contract
(`types.ts:210`).

### `ApiProvider` contract (`api-registry.ts:23`)

```
interface ApiProvider<TApi, TOptions> {
  api: TApi;
  stream: StreamFunction<TApi, TOptions>;
  streamSimple: StreamFunction<TApi, SimpleStreamOptions>;
}
```

Every provider implements two functions:
- `stream<X>` — the full provider-specific options surface.
- `streamSimple<X>` — receives `SimpleStreamOptions` (with `reasoning` level),
  maps it to provider-specific knobs, and delegates to `stream<X>`. This is where
  the unified `reasoning: "minimal".."xhigh"` is translated into Anthropic
  `effort`/budgets, OpenAI `reasoningEffort`, Google `thinkingBudget`/`thinkingLevel`,
  Bedrock `output_config.effort`, etc.

### `transform-messages.ts` — cross-provider normalization

Every provider calls `transformMessages(messages, model, normalizeToolCallId?)`
(`transform-messages.ts:64`) before converting to wire format. It is the **single
place that makes cross-provider handoffs and replay safe**. Two passes:

**Pass 1 (per-message transform):**
- `downgradeUnsupportedImages` (`transform-messages.ts:35`): if the target model
  lacks `"image"` in `input`, replaces image blocks in user/toolResult messages
  with text placeholders (collapsing consecutive ones).
- User messages pass through unchanged.
- Tool results get their `toolCallId` rewritten if a normalization map entry exists.
- Assistant messages: computes `isSameModel` (provider+api+id match,
  `transform-messages.ts:92`). Then per content block:
  - **thinking**: redacted thinking dropped for cross-model (opaque/model-specific);
    same-model thinking with a signature kept verbatim (needed for replay even if
    empty text); empty thinking dropped; otherwise for foreign models converted to
    plain `text` (`transform-messages.ts:98-114`).
  - **text**: kept (foreign → stripped of `textSignature`).
  - **toolCall**: strips Google `thoughtSignature` for foreign models; applies
    `normalizeToolCallId` and records the mapping so the matching tool-result id
    can be rewritten too (`transform-messages.ts:124-142`).

**Pass 2 (orphan repair):** Walks the transformed list and
- **skips errored/aborted assistant messages entirely** (`transform-messages.ts:192`)
  — incomplete turns shouldn't be replayed.
- inserts **synthetic tool results** (`"No result provided"`, `isError:true`) for
  tool calls that never got a result before the next assistant/user message or
  end of conversation (`insertSyntheticToolResults`, `transform-messages.ts:160`).
  This satisfies APIs that reject orphaned tool calls and preserves thinking
  signatures.

The `normalizeToolCallId` callback is provider-supplied because each API has
different id constraints (Anthropic `^[a-zA-Z0-9_-]+$`/64 chars; OpenAI Responses
`call_id|item_id`; Mistral 9-char; Bedrock 64-char; Google for Claude/gpt-oss only).

### `stream.ts` (root) vs `utils/event-stream.ts`

`src/stream.ts` is the **dispatcher** (`stream`/`complete`/`streamSimple`/
`completeSimple` + env-key injection). The actual **stream object** is
`AssistantMessageEventStream` in `utils/event-stream.ts` (see §4). Each provider
constructs one, runs an async IIFE that pushes events, and returns it
synchronously.

## 3. Provider files

All providers share a skeleton: build an `output: AssistantMessage` accumulator,
push `{type:"start"}`, iterate the upstream stream pushing normalized events,
maintain a per-block `index`/`partialJson` scratch (stripped before persisting),
compute `usage`+`calculateCost`, then push `done` or `error`. They catch all
errors and encode them as `stopReason:"error"|"aborted"` + `errorMessage`.

### Anthropic Messages — `providers/anthropic.ts` (`anthropic-messages`)

Targets the Anthropic Messages API via `@anthropic-ai/sdk`, but **hand-parses the
SSE stream itself** (`iterateSseMessages`/`iterateAnthropicEvents`,
`anthropic.ts:348,407`) for robustness (repairs JSON, requires `message_stop`,
surfaces `error` events). Used by many Anthropic-*compatible* providers too
(Fireworks, MiniMax, Kimi, Vercel AI Gateway, Cloudflare AI Gateway→anthropic,
some OpenCode, GitHub Copilot Claude-4).

Notable quirks:
- **Prompt caching** (`getCacheControl`, `anthropic.ts:53`): `cacheRetention`
  `short`→ephemeral, `long`→`ttl:"1h"` (gated by `supportsLongCacheRetention`),
  `none`→off. `cache_control` markers are placed on the system prompt, the **last
  tool** definition, and the **last user message content** (`convertMessages`
  `:1149`, `convertTools` `:1200`). `PI_CACHE_RETENTION=long` env is a backward-compat default.
- **OAuth "stealth mode"** (`anthropic.ts:68-105,847`): when the key looks like
  an OAuth token (`sk-ant-oat`, `isOAuthToken` `:779`), it sends Claude Code
  identity headers (`anthropic-beta: claude-code-20250219,oauth-2025-04-20`,
  `user-agent: claude-cli/2.1.75`, `x-app: cli`), injects the mandatory
  `"You are Claude Code…"` system block (`:910`), and **renames tools to Claude
  Code's canonical casing** (`Read`, `Bash`, …) outbound and back inbound
  (`toClaudeCodeName`/`fromClaudeCodeName` `:97,98`).
- **Thinking**: adaptive models (`compat.forceAdaptiveThinking`) use
  `thinking:{type:"adaptive",display}` + `output_config.effort`
  (`anthropic.ts:955`); older models use budget-based `thinking:{type:"enabled",
  budget_tokens}`. `thinkingDisplay` defaults to `"summarized"`. Beta headers:
  `interleaved-thinking-2025-05-14` (skipped for adaptive — built in),
  `fine-grained-tool-streaming-2025-05-14` (only when eager streaming unsupported,
  `shouldUseFineGrainedToolStreamingBeta` `:1176`). Empty/missing thinking
  signatures are converted to text unless `allowEmptySignature` (e.g. Xiaomi).
- **Compat detection** (`getAnthropicCompat` `:166`): Fireworks → no eager
  streaming, no long cache, no cache_control-on-tools, send session affinity;
  Cloudflare-AI-Gateway-anthropic → session affinity. `supportsTemperature:false`
  for Opus 4.7+ (temperature dropped, also dropped when thinking enabled).
- Cloudflare AI Gateway uses `cf-aig-authorization: Bearer` and nulls `x-api-key`;
  GitHub Copilot uses bearer + dynamic copilot headers.

### OpenAI Chat Completions — `providers/openai-completions.ts` (`openai-completions`)

The **most heavily compat-driven** provider. Targets `/v1/chat/completions` via
the `openai` SDK. Used by xAI, Groq, Cerebras, NVIDIA NIM, DeepSeek, Together,
zAI, Moonshot, OpenRouter, Vercel-via-completions, Cloudflare Workers AI, Xiaomi,
Ant Ling, HuggingFace, and any OpenAI-compatible endpoint (Ollama/vLLM/LM Studio).

- **`OpenAICompletionsCompat`** is resolved by `getCompat`→`detectCompat`
  (`openai-completions.ts:1161,1075`) which URL/provider-sniffs ~10 quirk flags,
  then overlaid by explicit `model.compat`. Flags govern: `store` field,
  `developer` vs `system` role, `reasoning_effort` support,
  `max_tokens` vs `max_completion_tokens`, strict tool mode, tool-result `name`
  requirement, "assistant message after tool result" bridging, thinking-as-text,
  `reasoning_content` on assistant replays (DeepSeek), session-affinity headers,
  long cache retention, and the `cacheControlFormat:"anthropic"` path.
- **`thinkingFormat`** (`openai-completions.ts:556-610`) is the big switch: emits
  the reasoning param in one of 8 dialects — `openai`(`reasoning_effort`),
  `openrouter`(`reasoning:{effort}`), `deepseek`(`thinking:{type}`+effort),
  `together`(`reasoning:{enabled}`+effort), `zai`/`qwen`(`enable_thinking`),
  `qwen-chat-template`(`chat_template_kwargs`), `string-thinking`(top-level
  `thinking`), `ant-ling`(`reasoning:{effort}` only for mapped efforts).
- **Streaming reasoning** is read from `reasoning_content`/`reasoning`/
  `reasoning_text` delta fields (first non-empty, to avoid Chutes duplication),
  `:318`. OpenRouter `reasoning_details` of type `reasoning.encrypted` are stored
  as `thoughtSignature` on the matching tool call (`:373`).
- **Assistant replay** sends content as a **plain string** (not block array) to
  avoid models (DeepSeek-via-NIM) mirroring the block structure (`:847`). Thinking
  is replayed under the model's reasoning-field key, or as text when
  `requiresThinkingAsText`.
- **Cache control** (`applyAnthropicCacheControl` `:643`) re-uses Anthropic-style
  `cache_control` markers (system/last-tool/last-message) for providers that
  understand them (e.g. OpenRouter `anthropic/*`). `prompt_cache_key` set for
  `api.openai.com` or long retention (`clampOpenAIPromptCacheKey`).
- Usage parse (`parseChunkUsage` `:1008`) follows OpenAI/OpenRouter semantics:
  `cached_tokens` = cache reads (not subtracted from), input =
  `prompt - cacheRead - cacheWrite`.
- Tool-call id normalization (`:753`): splits `call_id|item_id`, sanitizes,
  truncates to 40 for OpenAI.

### OpenAI Responses — `providers/openai-responses.ts` + `openai-responses-shared.ts`

`openai-responses` (used by `openai`, and Cloudflare-AI-Gateway→openai). Targets
`/v1/responses` via the `openai` SDK. The **message conversion + stream parsing
are shared** with Azure and Codex in `openai-responses-shared.ts`.

`openai-responses-shared.ts`:
- `convertResponsesMessages` (`:90`): builds `ResponseInput`; thinking blocks are
  replayed as their stored `reasoning` item (the whole item JSON is the
  `thinkingSignature`, `:175`); text blocks get a `TextSignatureV1` id
  (`encodeTextSignatureV1` `:40` — `{v:1,id,phase}`); tool calls are encoded as
  `call_id|item_id`, with foreign tool-call item ids rebuilt via
  `buildForeignResponsesItemId` (`fc_<hash>`, `:104`) and `id` omitted for
  different-model messages to dodge reasoning↔toolcall pairing validation (`:207`).
- `processResponsesStream` (`:288`): the shared SSE event reducer mapping
  `response.output_item.added/...delta/...done` and `response.completed` into the
  unified event protocol. Reasoning summary vs reasoning text both feed thinking
  deltas; usage subtracts cached tokens from input (`:499`); status maps to stop
  reason and `toolCall` presence upgrades `stop`→`toolUse`.

`openai-responses.ts` itself: builds params with `reasoning:{effort,summary}` +
`include:["reasoning.encrypted_content"]`, sets `store:false`, applies
`prompt_cache_key`/`prompt_cache_retention:"24h"`, supports `service_tier`
flex/priority **cost multipliers** (`getServiceTierCostMultiplier` `:279`).

### OpenAI Codex Responses — `providers/openai-codex-responses.ts` (`openai-codex-responses`)

The most complex provider (~1500 lines). Targets ChatGPT's `chatgpt.com/backend-api/codex/responses`
for Codex subscription models. **Does not use the OpenAI SDK** — hand-rolled fetch
(SSE) and WebSocket transports sharing the same `processResponsesStream`.

- **Auth**: the OAuth access token is a JWT; `extractAccountId` (`:1414`) decodes
  the `chatgpt_account_id` claim and sends `chatgpt-account-id` + `Authorization:
  Bearer` + `originator: pi` headers.
- **Transport** (`StreamOptions.transport`): `"sse" | "websocket" | "websocket-cached" | "auto"`.
  Default `auto` tries WebSocket then falls back to SSE on transport failure (but
  not on API/protocol errors). WebSocket connections are **cached per `sessionId`**
  for 5 min (`SESSION_WEBSOCKET_CACHE_TTL_MS`, `:688`) and reused; cached-context
  mode sends only the input **delta** via connection-scoped `previous_response_id`
  (`buildCachedWebSocketRequestBody` `:1259`) since Codex rejects `store:true`.
- **Retry**: explicit exponential backoff with `retry-after(-ms)` parsing,
  terminal rate-limit detection (`isTerminalRateLimitError` `:106`), friendly
  usage-limit messages (`parseErrorResponse` `:1383`).
- Emits `diagnostics` on transport fallback (`appendAssistantMessageDiagnostic`).
- Registers WebSocket cleanup via `registerSessionResourceCleanup` (`:786`).
- Debug stats per session via `OpenAICodexWebSocketDebugStats` (`:713`).

### Azure OpenAI Responses — `providers/azure-openai-responses.ts` (`azure-openai-responses`)

Thin wrapper over `AzureOpenAI` SDK reusing the shared Responses conversion/parsing.
Quirks: resolves base URL from `AZURE_OPENAI_BASE_URL`/`AZURE_OPENAI_RESOURCE_NAME`
and **normalizes** `*.openai.azure.com`/`*.cognitiveservices.azure.com` roots to
`/openai/v1` (`normalizeAzureBaseUrl` `:170`); deployment names treated as model
ids unless overridden by `azureDeploymentName` or `AZURE_OPENAI_DEPLOYMENT_NAME_MAP`
(`resolveDeploymentName` `:35`); `apiVersion` defaults `v1`. Responses-API only;
legacy deployment URLs unsupported.

### Google Generative AI — `providers/google.ts` + `google-shared.ts` (`google-generative-ai`)

Uses `@google/genai` (`GoogleGenAI`) `generateContentStream`.

- **No function-call streaming**: each `functionCall` part emits
  `toolcall_start`/`delta`(full args)/`end` in one go (`google.ts:195-202`).
- **Thought signatures**: `thought:true` marks thinking parts (`isThinkingPart`,
  `google-shared.ts:33`); `thoughtSignature` can ride on any part type and is
  preserved per-block (`retainThoughtSignature` `:46`). Signatures only kept for
  same-provider+model and valid base64 (`resolveThoughtSignature` `:63`).
- **Thinking config** (`google.ts:369`): Gemini 3 Pro/Flash & Gemma 4 use
  `thinkingLevel` (`MINIMAL..HIGH`); Gemini 2.x uses `thinkingBudget` (per-model
  budgets in `getGoogleBudget` `:463`, `-1` dynamic, `0` disabled). Gemini 3 can't
  fully disable thinking → lowest level without `includeThoughts`
  (`getDisabledThinkingConfig` `:412`).
- Tools use `parametersJsonSchema` (full JSON Schema); `useParameters` mode emits
  OpenAPI-style `parameters` for Cloud Code Assist + Claude (`convertTools`
  `google-shared.ts:272`). `StringEnum` exists because Google rejects
  `Type.Enum`'s anyOf/const.
- Tool-call ids only sent for Claude/gpt-oss models (`requiresToolCallId` `:70`).
  Gemini < 3 needs images in a separate user turn; Gemini 3+ supports multimodal
  `functionResponse.parts` (`supportsMultimodalFunctionResponse` `:80`).
- Tool-call ids generated locally if missing/duplicate.

### Google Vertex — `providers/google-vertex.ts` (`google-vertex`)

Near-clone of `google.ts` but constructs `GoogleGenAI({vertexai:true,...})` with
either a **Vertex API key** (`createClientWithApiKey` `:346`) or **ADC** with
`project`+`location` (`createClient` `:331`, from `GOOGLE_CLOUD_PROJECT`/
`GOOGLE_CLOUD_LOCATION`). `resolveApiKey` (`:397`) ignores the
`<authenticated>`/`gcp-vertex-credentials` placeholder markers so it falls back
to ADC. Custom base URLs and `{location}` templating handled in `buildHttpOptions`.

### Amazon Bedrock Converse — `providers/amazon-bedrock.ts` (`bedrock-converse-stream`)

Uses `@aws-sdk/client-bedrock-runtime` `ConverseStreamCommand`. Node-only.

- **Auth/region**: SigV4 by default; **bearer token** path
  (`AWS_BEARER_TOKEN_BEDROCK` / `options.bearerToken`) sets
  `authSchemePreference:["httpBearerAuth"]` (`:182`). Region resolution prefers
  explicit option > `AWS_REGION`/`AWS_DEFAULT_REGION` > `us-east-1` (left undefined
  when `AWS_PROFILE` set so the SDK resolves it). Standard endpoints only pinned
  when no region/profile configured (`shouldUseExplicitBedrockEndpoint` `:920`),
  preserving custom VPC/proxy endpoints.
- **Custom headers** injected via a Smithy `build`-step middleware so they're
  inside SigV4 signing; reserved `x-amz-*`/`authorization`/`host` skipped
  (`addCustomHeadersMiddleware` `:326`, `isReservedHeader` `:314`).
- **Prompt caching** via `cachePoint` blocks on system + last user message, only
  for cache-capable Claude models (`supportsPromptCaching` `:602`, override
  `AWS_BEDROCK_FORCE_CACHE=1`); `long`→`CacheTTL.ONE_HOUR`.
- **Thinking**: adaptive (`thinking:{type:"adaptive"}` + `output_config.effort`,
  Opus 4.6-4.8/Sonnet 4.6) vs budget-based; signatures only for Claude
  (`supportsThinkingSignature` `:629`) — non-Claude reasoning sent without
  signature; GovCloud omits `display` (`:952`).
- HTTP proxy support via `NodeHttpHandler` (HTTP/2 default lacks proxy support);
  `AWS_BEDROCK_FORCE_HTTP1`/`AWS_BEDROCK_SKIP_AUTH` escape hatches.
- Errors get human-readable prefixes (`formatBedrockError` `:297`) that the
  overflow detector keys off.

### Mistral Conversations — `providers/mistral.ts` (`mistral-conversations`)

Uses `@mistralai/mistralai` `chat.stream`. Tool-call ids normalized to **9
alphanumeric chars** with collision-avoidance (`createMistralToolCallIdNormalizer`
`:153`). Reasoning is either `promptMode:"reasoning"` (most reasoning models) or
`reasoningEffort:"none"|"high"` for a specific allow-list (`usesReasoningEffort`
`:590`). Session caching via `x-affinity` header (`:229`). Thinking content arrives

## 4. Streaming model

### `utils/event-stream.ts`

`EventStream<T,R>` (`:4`) is a generic push/pull async-iterable queue: producers
`push(event)`; consumers `for await`; a `finalResultPromise` resolves when an event
satisfies `isComplete`. `AssistantMessageEventStream` (`:69`) specializes it:
`isComplete = type==="done"||"error"`, and `result()` returns the final
`AssistantMessage` (the `done.message` or the `error.error`). This is why
`complete = stream(...).result()` works even on failures — the error path still
resolves a (partial) message.

### The event protocol (`types.ts:358`)

`start` → interleaved `{text,thinking,toolcall}_{start,delta,end}` (each carrying
`contentIndex` into `partial.content` and a live `partial: AssistantMessage`) →
terminal `done` (reason ∈ stop/length/toolUse, `message`) **or** `error`
(reason ∈ aborted/error, `error`). Key invariant documented in the README:
**events for different blocks may interleave**, so consumers must key off
`contentIndex`, never assume contiguous per-block sequences.

### How providers normalize into it

Each provider maintains an `output.content` array of blocks plus per-block scratch
(`index` to map upstream block ids, `partialJson`/`partialArgs` for incremental
tool args). On each upstream delta they mutate the block, run
`parseStreamingJson` for tool args, and push the matching event with the current
`output` as `partial`. On block stop they push `*_end` and **strip scratch fields**
so the persisted/replayed message only carries clean parsed data
(e.g. `anthropic.ts:649`, `openai-completions.ts:197`). Streaming-tool-arg JSON is
made resilient by `parseStreamingJson` (`utils/json-parse.ts:104`), which tries
strict parse → `repairJson` → `partial-json` → repaired-partial, always returning
at least `{}`. Anthropic's SSE is hand-decoded; Codex parses SSE/WebSocket frames
by hand; OpenAI/Azure use the SDK iterator; Google/Mistral/Bedrock use their SDK
async iterables.

## 5. Models & image models

### Chat models — `models.ts` + `models.generated.ts`

`models.generated.ts` exports `MODELS: { [provider]: { [id]: Model } }` (each entry
`satisfies Model<"...">`). `models.ts:7` flattens it into a `Map<provider, Map<id,
Model>>` at module load. `getModel`/`getModels` use conditional types
(`ModelApi`, `models.ts:15`) to infer the exact `TApi` of a literal provider+id,
which propagates the right `compat` shape and provider option types.

Helpers: `calculateCost` (`models.ts:39`) computes `$ = (rate/1e6)*tokens` per
component into `usage.cost`. `getSupportedThinkingLevels`/`clampThinkingLevel`
(`:50,61`) interpret `model.thinkingLevelMap` (`null` = unsupported,
`xhigh` requires explicit entry) and clamp a requested level to the nearest
supported one.

### Image models — `image-models.ts` + `image-models.generated.ts`

Parallel structure: `IMAGE_MODELS: { openrouter: { [id]: ImagesModel } }`,
flattened by `image-models.ts:6`. `ImagesModel` (`types.ts:600`) drops chat-only
fields and adds `output:("text"|"image")[]`. `getImageModel(s)`/`getImageProviders`
mirror the chat catalog API.

### Generation — `scripts/generate-models.ts` (and `generate-image-models.ts`)

A build-time script (`npm run generate-models`) that:
1. Fetches **models.dev** (`api.json`) as the primary catalog
   (`loadModelsDevData` `:505`), plus **OpenRouter** (`fetchOpenRouterModels`
   `:389`), **Vercel AI Gateway** (`fetchAiGatewayModels` `:447`), and the live
   **NVIDIA NIM** id list (`fetchNvidiaNimModelIds` `:369`).
2. Filters to **tool-capable** models only (`tool_call === true`/`tools` param).
3. Maps each provider's raw record to the unified `Model` shape, assigning the
   correct `api`, `baseUrl`, pricing (converted to `$/million`), and provider-specific
   `compat`/`headers`/`thinkingLevelMap` (e.g. Together/NVIDIA/Moonshot/zAI compat
   constants, Cloudflare base-URL routing by upstream, GitHub Copilot Claude-4 →
   `anthropic-messages` vs gpt-5 → `openai-responses`, Xiaomi token-plan variants,
   Fireworks session-affinity compat).
4. `applyThinkingLevelMetadata` (`:261`) stamps per-model thinking quirks
   (adaptive thinking flags, `xhigh` mapping, Gemini levels, DeepSeek-V4 map, etc.).
5. Applies hard-coded **overrides** (cache-pricing corrections, context-window
   fixes, missing Opus 4.6/4.7 profiles) before serializing `MODELS` to the
   `.generated.ts` file.

The generated files are **not hand-edited**; understanding their shape (above)
and how the script derives `api`/`compat`/pricing is enough. New providers require
adding mapping logic here (per the README "Adding a New Provider" checklist).

## 6. Auth

### `env-api-keys.ts` — API key resolution

`getEnvApiKey(provider)` (`:163`) → first non-empty configured env var, via
`getApiKeyEnvVars` (`:91`) which maps each provider to its env var name(s).
Special cases:
- Anthropic prefers `ANTHROPIC_OAUTH_TOKEN` over `ANTHROPIC_API_KEY` (`:97`).
- GitHub Copilot → `COPILOT_GITHUB_TOKEN`.
- **Vertex** (`:171`): returns the sentinel `"<authenticated>"` if ADC creds +
  `GOOGLE_CLOUD_PROJECT` + `GOOGLE_CLOUD_LOCATION` are present.
- **Bedrock** (`:186`): returns `"<authenticated>"` for any of `AWS_PROFILE`,
  IAM keys, bearer token, ECS/IRSA credential sources.

`findEnvKeys` (`:148`) reports *which* vars are set (only true API-key vars, not
ambient AWS/Google creds). There's a Bun workaround (`getProcEnv` `:35`) reading
`/proc/self/environ` when `process.env` is empty in compiled Bun sandboxes
(bun#27802). Node fs/os/path modules are dynamically imported to stay
browser-safe (`:1-24`).

`stream.ts:22 withEnvApiKey` injects this key only when the caller didn't pass one.

### `oauth.ts` + `utils/oauth/*` — OAuth flows

`src/oauth.ts` (one line, `:1`) re-exports `utils/oauth/index.ts`, the public
`/oauth` entry point. It maintains an **OAuth provider registry**
(`oauth/index.ts:48`) of three built-ins (Anthropic, GitHub Copilot, OpenAI Codex),
with `getOAuthProvider`/`register`/`unregister`/`reset`. High-level helpers:
- `getOAuthApiKey(providerId, credsMap)` (`oauth/index.ts:135`): returns
  `{newCredentials, apiKey}`, **auto-refreshing** when `Date.now() >= creds.expires`.
- `refreshOAuthToken` (deprecated alias).

`OAuthProviderInterface` (`utils/oauth/types.ts:54`): `login(callbacks)`,
`refreshToken(creds)`, `getApiKey(creds)`, optional `modifyModels` (Copilot uses
it to rewrite `baseUrl` from the token's `proxy-ep`). `OAuthCredentials` =
`{refresh, access, expires, ...}`.

Provider implementations:
- **`anthropic.ts`**: authorization-code + **PKCE** with a local callback server
  on port 53692 (`startCallbackServer` `:98`), Claude Pro/Max scopes; supports
  pasting the redirect URL manually (headless). Token refresh subtracts a 5-min
  safety margin from `expires`.
- **`github-copilot.ts`**: **device-code** flow (`startDeviceFlow`/
  `pollForGitHubAccessToken`), then exchanges the GitHub token for a Copilot token
  at `/copilot_internal/v2/token` (`refreshGitHubCopilotToken` `:207`). Parses
  `proxy-ep` from the token to derive the API base URL
  (`getGitHubCopilotBaseUrl` `:80`), supports GitHub Enterprise domains, and
  **enables all known Copilot models** post-login (`enableAllGitHubCopilotModels`
  `:271`).
- **`openai-codex.ts`**: offers **two methods** via `onSelect` — browser
  (auth-code+PKCE, local server on port 1455) or device-code. Validates the JWT
  to extract `chatgpt_account_id` (`getAccountId` `:400`); refresh has no expiry
  margin.

Shared OAuth utils: `pkce.ts` (Web-Crypto S256 PKCE), `device-code.ts`
(`pollOAuthDeviceCodeFlow` — RFC 8628 polling with `slow_down` backoff + abort +
timeout, `:45`), `oauth-page.ts` (success/error HTML), `types.ts`.

`src/cli.ts` is the `login`/`list` CLI driving these providers and persisting to
`auth.json`.

## 8. Key data structures / message format (cited)

- A **provider response** always accumulates into `output: AssistantMessage`
  initialized identically across providers (e.g. `anthropic.ts:456`,
  `openai-completions.ts:119`), with `content:[]`, zeroed `usage`,
  `stopReason:"stop"`. Cost is recomputed on every usage update via
  `calculateCost` (`models.ts:39`).
- **`AssistantMessage`** (`types.ts:288`) — the single normalized output;
  `content` ∈ `(TextContent|ThinkingContent|ToolCall)[]`.
- **`ToolResultMessage`** (`types.ts:303`) — `content` ∈ `(TextContent|ImageContent)[]`,
  `toolCallId`/`toolName`/`isError`/`timestamp`.
- **Signatures** are the cross-turn continuity mechanism:
  `TextContent.textSignature` (`types.ts:238`, OpenAI Responses message id /
  `TextSignatureV1`), `ThinkingContent.thinkingSignature` (`types.ts:244`,
  Anthropic signature / OpenAI reasoning item JSON / Bedrock reasoning signature),
  `ToolCall.thoughtSignature` (`types.ts:262`, Google encrypted thought / OpenRouter
  encrypted reasoning). `ThinkingContent.redacted` (`types.ts:248`) marks
  safety-redacted thinking whose opaque payload lives in `thinkingSignature`.
- **Streaming event** shapes carry both a `partial: AssistantMessage` snapshot and
  a `contentIndex` (`types.ts:358-370`).
- **`Usage.cost`** is a nested object computed from `model.cost` ($/M-token rates,
  `types.ts:581`).

## 9. Gotchas, invariants & non-obvious design decisions

- **Errors are never thrown after a stream is created** — they are encoded as a
  terminal `error` event + `result()` resolving a partial message
  (`types.ts:210`, every provider's `catch`). `complete()` therefore never
  rejects on provider/runtime failure; check `stopReason`.
- **Lazy provider imports**: never statically import provider impl modules in
  `register-builtins.ts`; doing so would bloat browser bundles and break the
  Node-only Bedrock split (`register-builtins.ts:89,326`).
- **Browser/Vite safety**: Node modules (`fs`/`os`/`http`/`crypto`) are loaded via
  guarded dynamic `import("node:"+…)` everywhere (`env-api-keys.ts:1`,
  `openai-codex-responses.ts:9`, oauth modules). Bedrock & OAuth login throw
  helpfully outside Node.
- **`transformMessages` is mandatory** before any wire conversion — it is the only
  place that downgrades unsupported images, converts foreign thinking → text,
  normalizes tool-call ids (with matching result-id rewrites), drops
  errored/aborted turns, and synthesizes results for orphaned tool calls. Skipping
  it breaks handoffs and replay.
- **Same-model vs foreign-model** replay: thinking blocks/signatures are only
  preserved when `provider+api+model` all match; otherwise thinking is flattened
  to plain text (no `<thinking>` tags, to avoid the model imitating them).
- **Streaming scratch fields** (`index`, `partialJson`, `partialArgs`,
  `streamIndex`) must be deleted before the block is persisted/replayed — every
  provider does this in both the `*_end` and `catch` paths.
- **Tool-call id constraints differ per API** and are encoded into the
  provider-supplied `normalizeToolCallId`. The Responses `call_id|item_id` scheme
  (`openai-responses-shared.ts:104`) is the trickiest: foreign tool calls get a
  hashed `fc_*` item id, and item ids are omitted for different-model messages to
  avoid OpenAI's reasoning↔toolcall pairing validation.
- **Usage/caching semantics are not uniform**: OpenAI/Responses report cached
  tokens *inside* input (subtracted out); Anthropic/Bedrock report cache
  read/write separately; Google folds `thoughtsTokenCount` into output. Read each
  provider's usage parse carefully.
- **Prompt caching has 3+ conventions**: Anthropic `cache_control` markers,
  OpenAI `prompt_cache_key`/`prompt_cache_retention`, Bedrock `cachePoint` blocks,
  plus session-affinity headers (Fireworks `x-session-affinity`, Mistral
  `x-affinity`, completions `session_id`/`x-client-request-id`). All gated by
  `cacheRetention` (`none`/`short`/`long`) and `sessionId`. `cacheRetention:"none"`
  also disables the cache `sessionId` passthrough.
- **`compat` is conditionally typed by API** (`types.ts:591`) and resolved by
  per-provider `getCompat` that overlays explicit `model.compat` on URL/provider
  auto-detection. Custom endpoints rely on this to declare quirks.
- **Thinking-level mapping** flows: `SimpleStreamOptions.reasoning` →
  `clampThinkingLevel` (via `thinkingLevelMap`) → provider `streamSimple` →
  provider-specific param. `null` in the map means unsupported; `off` may map to a
  literal provider value (e.g. `"none"`).
- **Anthropic OAuth stealth mode** silently rewrites tool names to Claude Code's
  casing and injects a Claude Code system block — surprising if you inspect
  payloads with `onPayload`.
- **Temperature is conditionally dropped**: incompatible with extended thinking and
  unsupported on Opus 4.7+ (`anthropic.ts:936`).
- **`onPayload`/`onResponse`** hooks let callers inspect/replace the exact provider
  payload and observe HTTP status/headers — the main debugging tool.
- **Bedrock custom headers** must go through the Smithy build-step middleware to be
  covered by SigV4; reserved headers are silently ignored (`amazon-bedrock.ts:312`).
- **Google has no tool-call streaming**: a single synthetic `toolcall_delta` with
  full args is emitted (documented in README and `google.ts:195`).
- **Codex `store:true` is rejected**; WebSocket continuation uses connection-scoped
  `previous_response_id` deltas instead, and WebSocket sessions expire after 5 min
  idle.

## Mental model in one paragraph

`getModel(provider, id)` returns a typed `Model` whose `api` field selects an
implementation from the API registry. `stream()` injects an env key, calls that
implementation, and returns an `AssistantMessageEventStream`. The implementation
runs `transformMessages` (image downgrade, foreign-thinking flattening, tool-id
normalization, orphan repair) → converts `Context` to the provider's wire format
→ opens the upstream stream → reduces upstream chunks into the unified
`{start,text/thinking/toolcall *,done|error}` event protocol while accumulating an
`AssistantMessage` with normalized `Usage`/cost → resolves that message via
`result()`. Auth, caching, thinking levels, and quirks are all parameterized by
the model's `compat`/`thinkingLevelMap` and `StreamOptions`, with OAuth and the
model catalog generated/managed out-of-band.
